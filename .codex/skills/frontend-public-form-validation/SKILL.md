# 사용자 공개 폼 유효성

## 보호 규칙

- 사용자가 명시적으로 요청하지 않으면 디자인, 라벨, placeholder, 필드 순서, DOM 구조, 클래스, 문구를 바꾸지 않는다.
- 하드코딩 내용을 데이터 바인딩으로 바꿀 때도 같은 시각 위치와 마크업 구조를 유지한다.
- Blade에는 인라인 `style`, `onclick`, `<style>`, `<script>`를 남기지 않는다.

## 작업 순서

1. 관련 폼, Form Request, 컨트롤러, 라우트, JS 파일을 확인한다.
2. 검증 key를 나열하고 각 key를 화면의 입력 또는 입력 그룹에 매핑한다.
3. 상단에만 있는 오류 요약은 필드별 `@error('field')` 출력으로 바꾼다.
4. 배열 필드는 관련 반복 블록 바로 아래에 그룹 오류를 표시한다.
5. 클라이언트 동작은 `public/js/frontend/...`에 두고 기존 로딩 패턴으로 불러온다.
6. 휴대폰 번호는 서버에서 숫자만 저장/비교하고, 화면 표시는 JS에서 하이픈을 넣을 수 있다.
7. 중복 확인/인증 버튼은 프로젝트의 기존 alert/API 패턴을 사용한다.

## 검증

- 관련 없는 디자인/문구/필드 변경이 없는지 확인한다.
- 변경한 Blade 파일에서 `style=`, `onclick=`, `<style`, `<script`를 검색한다.
- 가능한 경우 변경한 PHP 파일에 `php -l`을 실행한다.
- Form Request rule key와 Blade `@error` key가 일치하는지 확인한다.
